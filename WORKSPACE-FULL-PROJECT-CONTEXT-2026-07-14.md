## 3. Релизная цель

Целевой выпуск:

> **IRGEZTNE Workspace 1.0.0**

Оставшиеся 10% — восстановление существующих частей, интеграция, исправление дефектов, релизная полировка, общий тест и упаковка.

## 8. Верхняя навигация Web Studio

Сначала нужно привести в порядок «крышу», затем внутренние экраны.

Верхняя навигация должна иметь:

- одного активного владельца;
- единый реестр вкладок;
- единый RU/EN-механизм;
- предсказуемое переключение;
- отсутствие поздних перерисовок;
- отсутствие дублирующих маршрутов;
- нормальное поведение на узкой ширине.

### Текущий RU/EN-дефект

При переключении языка как минимум вкладки:

- `Редактор`
- `Шаблоны`

могут перерисовываться на английский при активном русском интерфейсе.

Сначала определить:

1. кто строит текущий массив вкладок;
2. кто обновляет подписи при смене языка;
3. кто поздним слоем повторно перерисовывает часть навигации;
4. кто владеет активным состоянием вкладки.

Не исправлять это случайной заменой текста.

### Шаблоны

`Шаблоны` — отдельный верхний слой Web Studio, добавленный позднее.

Он не должен быть смешан с созданием сайта.

В Templates должна существовать понятная команда:

> **Выбрать шаблон**

Ожидаемый маршрут:

```text
Шаблоны
→ карточка/предпросмотр
→ выбрать шаблон
→ существующий Web Studio template flow
```

Не создавать второй каталог.

### Настройки сайта

Речь не о глобальном модуле `Инструменты` Workspace.

Речь о существующей панели **«Настройки сайта»**, которая сейчас находится внутри слоя `Сайты`, под текущим сайтом.

Принятое направление:

- структурно вынести `Настройки сайта` в верхнюю навигацию Web Studio;
- сделать это только как настоящий first-class route/tab;
- не добавлять новый overlay поверх старого;
- не дублировать панель;
- после принятого переноса убрать старую кнопку под сайтом;
- оставить одну кнопку, одну панель и один маршрут.

Запрещённый «бутерброд»:

```text
Web Studio
└─ Сайты
   └─ Настройки
      └─ ещё один слой поверх
```

## 10. Активный редактор Web Studio

Активная цепочка:


Основа:

- ручные команды форматирования;
- собственная вставка HTML;
- собственный bridge сохранения;
- собственные медиаблоки.

Родительский bridge:

```text

saveEditorWorkbenchPayloadV084B
handleEditorWorkbenchMessageV084B
mountEditorWorkbenchV084B
```

### Уже проверено

Работали:

- ввод и вставка текста;
- Bold, Italic, Underline, Strike;
- цвета;
- заголовки;
- цитата;
- списки;
- Undo/Redo;
- Emoji;
- ссылки;

- видео по URL;
- HTML-режим;
- сохранение;

### Известные проблемы

- серый фиксированный холст;

2. обычный текст и вставка;
3. unlink;
4. изображения;
5. видео;
6. повторное открытие;
7. Preview;
8. ZIP/publish.

## 11. Tiptap и другие редакторы

В проекте присутствуют зависимости Tiptap, TinyMCE и Jodit.

Был создан отдельный Tiptap sandbox.

Вывод:

- Tiptap легче и предсказуемее на базовом тексте;
- но внедрение потребовало бы новой интеграции медиахранилища, bridge, HTML, Preview и Web Studio flow.

Текущее решение:

> Не переводить Web Studio на Tiptap вслепую.

Tiptap остаётся экспериментальным запасным направлением.

Активным редактором остаётся Workbench.

Не держать три пользовательских редактора. Цель — один релизный редактор.

- анонимная;
- лёгкая;
- по духу похожая на Umami;
- не копия Umami;
- без рекламного профилирования.

```text

```


- raw IP;

- path;

Оставшаяся работа:

IRGEZTNE Workspace 1.0.0 готов, когда:

- верхняя навигация не выглядит собранной разными слоями;

- релизные сборки проверены;
- документация соответствует реальности;
