# Workspace v1 Product Map

## 1. Основной принцип

Workspace организует не набор независимых экранов, а
рабочую цепочку:

`проект → действие → материал → инструмент → результат`

## 2. Фундаментальные модули

### Files

Владеет:

- локальными файлами;
- изображениями;
- ассетами;
- импортированными материалами;
- результатами файловых операций.

### Projects

Владеет:

- рабочими контейнерами;
- связями между материалами;
- контекстом работы;
- перечнем связанных задач и результатов.

### Office

Владеет:

- текстовыми документами;
- HTML/Markdown-материалами;
- будущими офисными объектами;
- сохранением и повторным открытием документов.

Office не обязан самостоятельно реализовывать каждый
редактор.

Он может использовать встраиваемые инструменты.

### Notes

Владеет:

- быстрыми записями;
- фрагментами;
- ссылками;
- рабочими черновиками.

### Tasks

Владеет:

- задачами;
- статусами;
- сроками;
- связями с проектами;
- источниками работы;
- результатами работы.

### Web Studio

Владеет:

- сайтами;
- страницами;
- настройками сайта;
- меню;
- дизайном;
- предпросмотром;
- экспортом и публикацией.

Внутренние разделы Web Studio:

- Сайты;
- Настройки;
- Шаблоны;
- Мастерская;
- Редактор;
- Страницы;
- Меню;
- Дизайн;
- Предпросмотр;
- Сервер;
- Опубликовать.

### Chat

Владеет рабочим общением.

Его развитие не должно блокировать local-first работу
остальных модулей.

## 3. Tools

Tools является каноническим каталогом всех прикладных
инструментов.

Возможные группы:

- документы и текст;
- данные и таблицы;
- изображения и медиа;
- конвертация;
- схемы и визуализация;
- формулы;
- веб-инструменты;
- информационные инструменты.

Инструмент не обязан быть отдельным фундаментальным
модулем.

## 4. Workshop

Workshop является частью Web Studio, но имеет собственную
полноформатную авторскую поверхность.

Владеет пакетами Web Studio:

- шаблоны;
- темы;
- блоки;
- виджеты;
- ассеты;
- стартовые наборы;
- версии;
- совместимость;
- валидация.

Workshop не является универсальным каталогом
пользовательских инструментов.

## 5. Рабочие объекты

Предварительный список:

- Project;
- Task;
- File;
- Image;
- Document;
- Note;
- Table;
- Dataset;
- Diagram;
- Formula;
- Presentation;
- Site;
- Page;
- Package.

Не все объекты обязаны быть реализованы в первой
итерации.

Архитектура не должна мешать их последующему добавлению.

## 6. Правило владения

Модуль хранит объект и его жизненный цикл.

Инструмент:

- принимает объект или входные данные;
- выполняет работу;
- возвращает результат владельцу;
- не создаёт отдельную несовместимую копию объекта.

## 7. Примеры маршрутов

### Документ

`Project → Task → Office Document → редактор
→ HTML/PDF result → Task completed`

### Изображение

`Files → Image Converter → WebP result
→ Web Studio → Page`

### Данные

`Project → Task → Table Editor → Dataset/Table
→ export → result`

### Web Studio

`Site → Template → Editor → Preview → Export/Publish`

### Пакет

`Workshop → Validation → Templates → Site`
