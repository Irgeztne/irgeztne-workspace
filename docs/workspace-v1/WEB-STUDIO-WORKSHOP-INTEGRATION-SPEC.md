# Web Studio Workshop Integration — Product Specification

## 1. Цель

Интегрировать восстановленную Мастерскую в Web Studio,
не разрушая её полноформатный интерфейс и не создавая
второй независимый модуль.

## 2. Верхняя шапка

Кнопка `Мастерская / Workshop` добавляется сразу после
`Шаблоны / Templates`.

Принятый порядок:

1. Сайты
2. Настройки
3. Шаблоны
4. Мастерская
5. Редактор
6. Страницы
7. Меню
8. Дизайн
9. Предпросмотр
10. Сервер
11. Опубликовать

Шаблоны остаются прямой кнопкой.

Никакого выпадающего меню для Шаблонов и Мастерской.

## 3. Поведение перехода

При нажатии `Мастерская`:

- браузерная оболочка Workspace остаётся;
- логотип остаётся;
- верхняя браузерная панель остаётся;
- шапка Web Studio остаётся;
- меняется только центральная рабочая страница.

## 4. Рабочая поверхность

Мастерская открывается в центральной области Web Studio.

Она сохраняет:

- полноформатную ширину;
- обзор;
- список пакетов;
- создание пакета;
- редактирование;
- файлы;
- превью;
- совместимость;
- валидацию;
- архив;
- восстановление;
- удаление.

## 5. Техническая совместимость

Не заменять существующую Мастерскую новой реализацией.

Сохранить:

- route `codehub`;
- `window.NSCodeHubV1`;
- существующий CodeHub store;
- storage key;
- текущую модель пакета.

## 6. Навигация внутри Мастерской

Встроенная Мастерская не должна показывать дублирующий
ряд навигации всего Workspace:

`Главная · Файлы · Проекты · Офис · ...`

Пользователь уже находится в оболочке Web Studio.

Локальная навигация Мастерской сохраняется и позднее
может развиваться отдельно.

## 7. Контекст сайта

В обычных разделах Web Studio справа показывается
текущий сайт.

В режиме Мастерской контекст должен честно отражать,
что пользователь работает с локальными пакетами, а не с
текущей страницей сайта.

Возможная подпись:

- Мастерская;
- Локальные пакеты.

При возврате в обычный раздел снова показывается
текущий сайт.

## 8. Роли Шаблонов и Мастерской

Шаблоны:

- просмотр готовых вариантов;
- реальное превью;
- выбор;
- применение к сайту.

Мастерская:

- создание;
- сборка;
- редактирование;
- проверка;
- подготовка пакета.

## 9. Приёмка

Интеграция принимается, если:

1. Кнопка Мастерской видна в шапке Web Studio.
2. Шаблоны остаются прямой кнопкой.
3. При переключении не исчезает оболочка Web Studio.
4. Центральная область полностью отдаётся Мастерской.
5. Существующие пакеты доступны.
6. Новый пакет создаётся.
7. RU/EN работают.
8. Светлая и тёмная темы не ломаются.
9. Возврат в другие разделы Web Studio работает.
10. Дублирующая навигация Workspace не показывается.
11. Office, Files, Tasks и стартовая страница не
    изменяются.

## 10. Граница этапа

Этот этап не включает:

- перестройку главной Workspace;
- развитие Tools;
- реализацию Tasks;
- изменение формата пакетов;
- создание облачного каталога.
