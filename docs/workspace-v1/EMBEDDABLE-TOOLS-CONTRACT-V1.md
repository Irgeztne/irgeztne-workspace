# Embeddable Tools Contract v1

## 1. Назначение

Один инструмент должен использоваться из разных модулей,
не создавая отдельных реализаций.

## 2. Каноническое место

Каждый прикладной инструмент зарегистрирован в разделе
`Tools`.

Tools является каталогом и точкой самостоятельного
запуска.

## 3. Дополнительные точки запуска

Инструмент может открываться из:

- Files;
- Projects;
- Office;
- Notes;
- Tasks;
- Web Studio;
- других разрешённых хостов.

## 4. Основной контракт

Инструмент должен принимать:

- `tool_id`;
- `host_module`;
- `project_id`;
- `task_id`;
- входной объект или ссылку;
- режим открытия;
- локаль;
- тему.

Инструмент должен возвращать:

- статус операции;
- созданные результаты;
- изменённые объекты;
- предупреждения;
- ошибки;
- метаданные сохранения.

## 5. Владение данными

Инструмент не должен без необходимости владеть
окончательным рабочим объектом.

Результат сохраняется владельцем:

- Files сохраняет файл;
- Office сохраняет документ;
- Projects сохраняет связь;
- Web Studio сохраняет сайт или страницу;
- Tasks сохраняет ссылку на результат.

## 6. Состояние инструмента

Допускается хранение:

- пользовательских настроек;
- последних параметров;
- безопасного временного черновика;
- истории операции, если она нужна пользователю.

Не допускается:

- скрытая копия всех входных файлов;
- отдельная база тех же документов;
- несовместимый объект, который нельзя открыть вне
  инструмента.

## 7. Manifest

Каждый инструмент должен иметь manifest.

Предварительные поля:

- id;
- name_ru;
- name_en;
- version;
- category;
- description_ru;
- description_en;
- accepted_inputs;
- produced_outputs;
- supported_hosts;
- capabilities;
- storage_policy;
- permissions;
- offline;
- theme_support;
- locale_support.

## 8. Поверхности

Один инструмент может предоставлять:

- компактную панель;
- полноформатную поверхность;
- встроенный блок;
- диалог операции.

Не каждый инструмент обязан поддерживать все четыре
режима.

## 9. Навигация

При запуске из контекста инструмент должен знать:

- откуда он открыт;
- с каким объектом;
- куда вернуть результат;
- куда вернуться после завершения.

## 10. Темы и локализация

Обязательно:

- RU;
- EN;
- светлая тема;
- тёмная тема;
- отсутствие сброса данных при переключении.

## 11. Ошибки

Ошибка должна:

- быть понятной;
- не уничтожать исходный объект;
- позволять повторить операцию;
- показывать, был ли создан частичный результат.

## 12. Импорт и экспорт

Для каждого инструмента должна быть честная матрица:

`входной формат → сохраняемые свойства
→ выходной формат → ограничения`

## 13. Предварительные кандидаты

Базовая рабочая польза:

- Image Converter;
- Document/HTML/Markdown operations;
- Table/Data Editor;
- CSV/JSON Converter;
- PDF operations.

Возможные последующие инструменты:

- Diagram Editor;
- Formula Editor;
- Presentation Builder;
- Weather;
- Compass;
- Chart;
- Data Mapper;
- Site Health.

## 14. Приёмка инструмента

Инструмент принимается, если:

1. Открывается из Tools.
2. Открывается хотя бы из одного рабочего контекста.
3. Принимает реальный входной объект.
4. Не повреждает источник.
5. Создаёт или изменяет полезный результат.
6. Возвращает результат владельцу.
7. Результат повторно открывается.
8. Работает после перезапуска.
9. Работает RU/EN.
10. Работает в двух темах.
