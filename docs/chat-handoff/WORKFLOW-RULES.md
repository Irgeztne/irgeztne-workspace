# IRGEZTNE Workspace — Workflow Rules

## Коммуникация

- Общение на русском.
- Обращение на `ты`.
- Давать практические команды, а не абстрактные обещания.
- Предпочтителен один копируемый terminal block.
- После успешного патча приложение обычно запускается автоматически.
- Не заставлять пользователя многократно проверять неподтверждённые гипотезы.

## Изменения проекта

Перед изменением:

1. доказать владельца;
2. показать границу;
3. создать checkpoint;
4. предусмотреть restore;
5. проверить точные маркеры исходного состояния.

После изменения:

1. структурная проверка;
2. проверка изменённых файлов;
3. запуск приложения;
4. визуальная приёмка конкретных поверхностей.

## Запрещённые практики

- широкие regex-патчи без полного контекста;
- изменение нескольких модулей одной гипотезой;
- объявление файла владельцем только по grep;
- удаление архивов до принятия;
- удаление media quarantine;
- автоматическое переименование технических routes;
- смешение Atlas и Workspace;
- создание лишних скачиваемых скриптов, когда достаточно команды;
- утверждение об успехе до визуального подтверждения.

## Текущие no-touch зоны

Пока идёт поиск CodeHub, не менять:

- Compact Office;
- Web Studio;
- Editor;
- Account;
- Chat;
- Weather;
- Atlas;
- Analytics Core;
- правильное верхнее внутреннее меню.

## Git и checkpoints

- Git фиксирует осмысленные состояния проекта.
- `_CHECKPOINTS` используется для локального безопасного отката.
- ZIP не заменяет Git и checkpoint.
- Handoff ZIP содержит только документацию и небольшие evidence-файлы.
