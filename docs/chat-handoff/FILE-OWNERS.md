# IRGEZTNE Workspace — File and Runtime Owners

## Electron load chain

`package.json → main.js → win.loadFile('index.html')`

Это подтверждает загружаемый HTML, но не делает `index.html` единственным runtime-владельцем интерфейса.

## `index.html`

Содержит:

- начальную разметку;
- панели модулей;
- исходные кнопки;
- исходные карточки;
- порядок подключения скриптов.

После загрузки его элементы могут быть:

- переименованы;
- пересозданы;
- переставлены;
- заменены runtime-скриптами.

## `src/legacy-shell.js`

Участвует в:

- маршрутизации секций;
- подписях модулей;
- описаниях;
- повторной отрисовке отдельных поверхностей;
- обработке `codehub`, `documents`, `analytics`, `site-pages`.

Перед изменением нужно определить конкретную функцию и место вызова.

## `renderer.js`

Содержит крупную часть runtime-логики Workspace и может повторно строить отдельные поверхности.

Не изменять его широким regex-патчем.

## Главное правило owner-аудита

Совпадение названия, класса или route в файле не является достаточным доказательством владения.

Нужно доказать:

1. что файл загружается;
2. когда он загружается;
3. создаёт ли он конкретный DOM;
4. перерисовывает ли он DOM позже;
5. есть ли после него другой скрипт-владелец;
6. читает ли он сохранённый порядок или состояние.
