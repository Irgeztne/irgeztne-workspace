# IRGEZTNE Workspace — Project Context

## Продуктовая граница

В текущей экосистеме IRGEZTNE два основных продукта:

1. **IRGEZTNE Atlas** — публичный веб-продукт и система знаний.
2. **IRGEZTNE Workspace** — локальное загружаемое приложение на Electron.

Публичный сайт IRGEZTNE является родительским брендовым сайтом, а не третьим продуктом.

Atlas и Workspace находятся в разных рабочих деревьях. Их нельзя смешивать одним патчем.

## Активные каталоги

Workspace:

`~/Загрузки/irgeztne-workspace-main`

Atlas:

`~/Загрузки/irgeztne-atlas`

Резервные снимки:

`~/Загрузки/_CHECKPOINTS`

## Техническая основа Workspace

- Electron.
- `package.json` указывает `main.js`.
- `main.js` загружает корневой `index.html`.
- После начальной HTML-разметки несколько runtime-скриптов повторно создают, подписывают и переставляют интерфейс.
- Наличие текста в `index.html` не доказывает, что `index.html` является последним владельцем видимой поверхности.

## Стабильные технические маршруты

Видимое название `Мастерская / Workshop` использует технический route:

`codehub`

Видимое название `Задачи / Tasks` временно использует существующий технический route:

`analytics`

Эти технические маршруты пока не переименовывать.

## Общий принцип разработки

Каждая правка должна:

1. иметь доказанного runtime-владельца;
2. быть узкой;
3. создавать checkpoint;
4. иметь автоматический restore;
5. проходить структурную проверку;
6. не затрагивать соседние модули;
7. запускать приложение только после успешной установки.

Нельзя принимать grep-совпадение за доказательство владения интерфейсом.
