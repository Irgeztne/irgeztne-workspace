Quick start

Give readers the answer first, then details.

A good documentation page starts with orientation: what this page explains, who it is for, and what the reader can do next.

01

Install

Show the minimum setup without overwhelming the reader.

02

Configure

Explain the important settings and safe defaults.

03

Publish

Point the reader toward preview, export or deployment.

Documentation should feel calm, not empty.

Wide layouts are useful when they support reading: side navigation, article content, table of contents and examples all visible together.

API / Reference

Reference blocks should be structured and scannable.

GET

/sites

Returns a list of available sites and metadata.

POST

/publish

Starts export or publishing for the selected project.

PATCH

/settings

Updates SEO, OpenGraph, robots and custom settings.

Example request JSON 
{
  "siteId": "northline-journal",
  "template": "documentation",
  "locale": "ru",
  "publish": {
    "provider": "static-export"
  }
}
FAQ

Answer common questions before they become friction.

Can this template use images?

Yes, but documentation usually works best with code screenshots, interface examples, diagrams and tables.

Is RSS needed here?

It can be useful for changelogs or product updates, but it should not be presented as a social sharing icon.

Can users replace demo content?

Yes. Demo content is only for preview and should be replaced with real project documentation.
